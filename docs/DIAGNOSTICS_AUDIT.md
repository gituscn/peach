# 日志与诊断核验

核验范围覆盖 269 个 Python 模块的异常与子进程入口，以及浏览器错误上报、托盘、更新和诊断导出。静态枚举用于建立候选清单，各链路按故障语义复查；正常取消、缓存回退、来源未命中和任务互斥保留各自状态。

## 反馈入口

馆藏处理失败时，重试失败项，再从托盘「导出诊断报告」或系统诊断页「下载诊断报告」取得 ZIP。用户只需提供一个 ZIP。下载限运行 Peach 的本机，已登录的同源设备可以上报浏览器错误；开放访问模式不提供匿名远程上报。

错误发生时必须实际记录底层证据。完整问题清单位于 `state/library-processing-<job_id>.issues.jsonl`。通用问题清单不能还原被丢弃的 FFmpeg 错误；没有原始记录的历史失败需要重试取证。

## 证据链

| 链路 | 持久证据与核验 |
| --- | --- |
| 启动、CLI、托盘 | 配置及可选依赖加载前安装异常钩子；主线程、后台线程、unraisable、asyncio 和 warning/error 日志写入 `errors-*.log`，原生故障写入 `crash-*.log`；不可写时使用备用目录 |
| HTTP 请求 | 未处理异常与 HTTP 5xx 记录 traceback、方法、路由模板、状态码和 `error_id`；响应头 `X-Peach-Error-ID` 与记录关联；请求参数、正文和鉴权头不作为上下文采集 |
| 后台任务 | 异常记录任务键、job/run 编号、线程与 traceback；显式返回失败的操作记录失败消息；暂停、互斥和取消沿用任务协议 |
| 抽帧、拼图、探测 | 保留退出码、超时、采样位置、时长、工具来源、色彩重试和有界 stderr；`media-probe`、`preview`、`frame-capture`、`frame-tile` 与 `library-preview` 覆盖各入口 |
| 图片有效性 | Pillow 完整解码确认图片；纯色小 JPEG 可用，残片、非零退出和陈旧输出不能算生成成功 |
| 外部来源、下载 | 来源授权、限流、冷却与未命中使用领域状态；意外失败使用现有异常日志和任务回执；ZIP 包含来源健康状态与时间，来源响应原文留在本机 |
| 更新与回滚 | 安装、回滚失败保留 traceback；ZIP 包含启动准备、更新状态、源码更新日志、托盘重启日志及近期迁移日志 |
| 隧道 | ZIP 包含 `cloudflare-tunnel.log` 与脱敏运行状态 |
| 浏览器 | 保存消息、堆栈、脚本文件名、行列、页面与浏览器标识；查询参数不进入页面字段；同源、有效登录、每分钟条数和请求体积门槛有回归 |
| 媒体工具 | 诊断报告与 ZIP 检查实际版本、可执行性及 AV1 软件解码器；`/healthz` 只使用轻量路径检查，不执行外部工具 |

## 可选远程诊断

安装器、首次设置和设置页「应用与维护」提供「发送版本统计与错误诊断（推荐）」单个选项，默认勾选，同时控制版本统计与错误诊断，可取消勾选或在设置页关闭。静默安装保留已有选择。选项保存在本机 `state/remote-reporting.json`；没有记录时两项默认开启，已保存的关闭选择持续生效，损坏或只开启一项的记录均不发送。不写 ledger。缺少接收端时页面明确提示不会发送，仍可保存选择。

| 类别 | 发送内容与筛选 |
| --- | --- |
| 版本统计 | Peach 版本与操作系统类型，每机 UTC 自然日最多一次；在进程启动时尝试，没有安装标识，不能据此统计独立用户 |
| Python 错误 | 版本、平台、Python、CPU 架构、故障环节、异常类型链、Peach 文件名／函数名／行号、整数错误码；错误文本、变量、源码上下文与用户目录不发送 |
| HTTP 5xx | 追加方法、路由模板与关联错误编号；不含实例参数、查询参数、正文、鉴权头或用户网址 |
| 媒体工具 | 退出码，以及确定匹配的 AV1 解码器缺失、非法媒体、权限、磁盘空间或未知解码器类别；stderr 与媒体名称留在本机 |
| 浏览器错误 | 仅发送 Peach 正式脚本的行列位置；没有可定位堆栈的错误与扩展脚本不发送 |

正常取消、来源未命中／暂不可用、HTTP 4xx、互斥、普通 warning 和无堆栈的泛化日志不发送。后台任务的纯文本失败回执仍保留在本机；有异常链的意外失败可发送。每机每天最多 20 条错误，同类指纹每天一次，托盘和子服务共享额度文件；发送失败不补传历史。SDK 内部日志不进入远程钩子。

两项均通过公开 DSN 发送到 Sentry 托管服务，接收服务会接触连接 IP。客户端不发送 IP 字段、用户身份、设备标识、观看记录、媒体信息、凭据、完整日志或诊断 ZIP。发送队列不落盘，后台发送前复查本机同意版本；关闭或重新选择会让排队旧事件失效，已在途或已接收的请求无法撤回。本机 ZIP 导出独立可用。

接收端由维护者配置：源码与 Docker 使用 `PEACH_SENTRY_DSN`；Windows 发行构建从同名环境变量写入包内 `sentry.json`，GitHub Release 使用仓库变量 `PEACH_SENTRY_DSN`。只接受 Sentry 的公开 HTTPS DSN（含 US / DE 区域），不需要 API token。没有 DSN 时不会创建 SDK 客户端。SDK 自动框架集成、日志、性能追踪和指标均关闭；版本统计作为普通事件计入 Sentry 错误事件额度。账号套餐和总量以 [Sentry 订阅页](https://sentry.io/settings/) 为准。

回归验收使用临时数据根和 SDK 内存接收端。本机已配置独立的 `peach-errors` 与 `peach-library-research` 接收项目，合成错误 `PEACH-ERRORS-1` 已在 Sentry 核对代码位置；没有发送真实馆藏。发布工作流的两个公开 DSN 仓库变量已配置并回读核对，构建包从变量取得接收地址；配置变量不触发发布。技术诊断选择见 [ADR-0110](adr/0110-recommended-diagnostics-choice.md)。安装辅助进程只在本机取证，不初始化远程客户端或发送事件；应用进程按用户选择发送。

### 馆藏与口味群体研究

「馆藏与口味研究」是独立默认关闭的选项。首次设置说明入口；设置页先列出字段，再生成可滚动查看的完整本机 JSON 预览。用户还必须主动勾选「我已查看字段与预览，同意每周自动上传馆藏与口味明细用于 Peach 群体研究」，才可开启。服务端要求当前进程生成、10 分钟内有效的一次性预览凭据和当前字段版本；单独提交开关或打开错误诊断均不构成同意。关闭不要求预览或重新同意。

快照 `peach-library-taste.json` 包含：

- `schema`、`peach`、`period`：字段版本、Peach 版本和 UTC 自然周。
- `library`：规范作品编号、同编号文件数量、标签、规范人物／创作者／厂牌／系列名称、媒体类型、时长、评分、喜欢状态、累计播放次数与观看比例。同编号的多个文件合成一条；无编号的条目只含同一批元数据，不含内部行号或媒体标题。
- `preferences`：出演者、创作者、标签、厂牌、系列、年代和时长偏好的名称、强度与证据来源类别。复用现有 `preference_profile`；来源类别包括馆藏、观看反馈、已导入浏览记录、书签与关注，只发送派生偏好，不发送原始浏览网址、标题或时间线。

字段经过白名单投影；标签和规范名称中的网址、绝对路径与凭据样式继续经过现有脱敏函数。字段可反映成人内容偏好，完整馆藏组合也可能识别个人，因此界面明确说明「不能保证匿名」。不包含账号、设备标识、跨周期安装标识、文件名、路径、标题、媒体、搜索词或逐条浏览／观看记录。预览是当前数据；同意覆盖每周发送同一批字段的最新数据。增加字段时必须推进 `SCHEMA`，已有同意随之失效。

后台服务只有在有效同意和独立接收端同时存在时才读取明细并初始化 SDK。每机每 UTC 自然周最多尝试一次，跨进程共用尝试记录；不补传历史快照。附件最大 10 MiB，超出则拒绝整份快照。错误诊断传输不接受附件；研究传输只接受一条用途固定的事件与一个固定文件名的 JSON 附件，发送前再次复查同意版本。发送尝试记录不表示 Sentry 已接收。

维护者另设 `PEACH_LIBRARY_SENTRY_DSN`，Windows Release 读取同名仓库变量并写入包内 `library_dsn`。该 DSN 的项目必须与错误诊断项目不同，同项目配置视为未配置。研究快照作为 Sentry 附件接收，每次也产生一条事件；组织内的事件和附件额度仍共享。见 [Sentry 附件说明](https://docs.sentry.io/platforms/python/enriching-events/attachments/)。

群体分析按 `period` 分开汇总，区分作品持有率、标签分布、明确反馈和派生偏好；不能把文件数量当用户数量。每机每周一次只能降低重复，不能识别同一人多安装；没有跨周期用户标识，也不能跨周合并成个人画像。结果只代表自愿参与样本，安装覆盖率和选择偏差必须同时报告。接收端分析看板不属于客户端上传功能。

## ZIP 内容

- `report.json`：系统和版本信息、检查结果、媒体工具能力、来源健康摘要及文件收集回执。
- `logs/<目录序号>/`：托盘、服务、重启、首次扫描、源码更新、隧道、错误及崩溃日志；固定日志包含近期自然月分段。
- `processing/`：馆藏处理状态与近期问题清单、启动准备、自动更新、独立包更新及隧道状态。
- `updates/`：近期更新迁移日志。

每个文件读取尾部最多 96 KiB；错误日志最多 8 份、崩溃日志最多 4 份、处理问题清单最多 8 份、迁移日志最多 2 份。截断和读取失败进入收集回执，单个不可读文件不影响其他证据。JSON 与 JSONL 分别解析，正在写入的残行不进入共享报告。日志保留周期沿用半年及自然月分段策略。

ZIP 不包含 ledger、配置文件、私钥、登录 Cookie 或媒体文件。路径、网址、地址、凭据字段及命令行凭据值脱敏；处理记录中的媒体名称隐藏。故障注入的默认日志落在测试进程临时目录。

## AV1 样本

样本 SHA256 为 `97e67a7e9521de3771480ed4f4ffe21461f3d4d13d95e68bc46618524461ace0`，体积 55,805,806 字节，视频为 AV1、1280×700、26 fps、585.153855 秒。

未包含 `libdav1d` 的 FFmpeg 9.0.2 工具返回退出码 `69`，stderr 包含 `Your platform doesn't support hardware accelerated AV1 decoding` 和 `Function not implemented`。`scripts/build_ffmpeg_windows.sh` 静态编入固定版 dav1d；完整源码归档、许可证和 SHA256 清单通过 `media_tool_bundle.py --validate-only`。

自构建工具对同一原文件完成全部 9 个采样点及 1440×789 九宫格，原媒体只读。发行验收使用内嵌的合成 AV1 片段，在 CPU 上完成解码和抽帧，不依赖机器显卡或 AV1 编码器。

其余 52 项媒体未取得，不能据一个样本断言全部失败原因。AV1 修复随包含该工具构建的发行包交付；外部用户侧安装与剩余媒体重试尚未验证。

## 影响面

| 影响面 | 适用性 |
| --- | --- |
| 数据层 | 本机独立同意与限额文件；研究只读账本，复用派生偏好；没有迁移或真实 ledger 写入 |
| API／契约 | 诊断选择读写、完整研究预览与同意写入；本机、鉴权、同源限制 |
| 页面 | 配置页「应用与维护」、首次设置；Windows 安装器默认勾选推荐的诊断选项；其他馆藏页面不适用 |
| 反向状态 | 诊断与研究分别关闭；关闭使排队载荷失效，研究重新开启须预览并同意 |
| 视口 | 桌面和 390×844 手机验证明细折行、内部滚动、同意与关闭；无横向溢出 |
| 测试 | 诊断默认开启、取消与持久关闭、研究默认关闭、脱敏、白名单、限额、SDK 内存传输、权限及界面回归 |
| 文档 | 中英文 README、STATUS、REUSE、待办、本记录与 ADR-0109 |
| 智能体入口 | 没有新增规则、技能或入口 |
| 生产 | 本机源码运行态按托盘入口重启并严格校验 HTTPS；外部测试包发布独立验收 |
