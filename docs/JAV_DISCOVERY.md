# JAV 发现

发现用于找可能喜欢的作品。三个主分区为「我的馆藏」「发现」「想要」；发现内有「库外发现」和「馆藏探索」两种范围。

| 范围 | 候选 | 打开方式 |
| --- | --- | --- |
| 库外发现 | 已知、未入库、未忽略的作品，无发行日期阈值 | `/jav/movie/:code` 作品详情 |
| 馆藏探索 | 未看或只看过一次且进度不足一半的 JAV，排除看过标记、不合口味及已移除作品 | `/item/:id` 视频详情 |

## 已有数据

观看次数、观看时长、评分、喜欢及高潮记录参与已有口味汇总；浏览记录中的正向标签与人物信号也可参与。发现不把已标记不合口味的作品算作正向证据，也不由此否定整类标签。厂牌和系列沿用该汇总的实体维度。重复的同名投影合并，每个维度取口味排名前 30 个身份；匹配使用规范身份或唯一别名，不使用姓名子串。

推荐复用 `related.rank_related`：标签以 IDF 降低泛标签权重，出演者、厂牌、系列按已有身份匹配；MMR 减少近重复作品连续占据列表。发行时间只用于用户选择的排序。没有口味信号时不制造推荐理由，不把热门或近期作品冒充个性化推荐。

库外候选来自本机已知的 `feed_discovery`，并非全发行目录。取得过的作品详情在有效内存缓存内可补充标签、系列、厂牌和出演者；缓存未取得时只用候选中已有的字段，不因浏览发现页而批量联网或写账本。库内匹配使用账本中已有的规范实体与观看进度。每轮最多为 4,000 个匹配优先的候选做排序，返回至多 100 部；容量限制不是发行时间限制。同番号只显示一张卡。

## 资料与候选扩展方案

| 维度或能力 | 当前条件 | 取得和使用方案 |
| --- | --- | --- |
| 标签、题材、场景、外观 | 库内有规范标签；库外详情可能有来源标签 | 用户打开作品详情时取资料；按已核对的实体别名匹配，未知词保留来源，不能猜成已有标签 |
| 系列、厂牌 | 库内实体及部分库外资料可用 | 详情取得后补足候选属性，避免单一女优占满推荐 |
| 历史作品目录 | 当前候选只覆盖已知作品 | 按口味人物、厂牌、系列和标签调用公开目录的有界分页，逐页去重、排除已入库及忽略项；请求尊重来源间隔，不以“新作”接口代替全目录 |
| 年代、时长、质量与热度 | 部分作品详情有字段，口味汇总未提供对应分布 | 先记录资料覆盖率，再按完播、评分和喜欢构建偏好；来源评分仅作质量参考，不等同个人口味 |
| 相似作品与探索比例 | 已有标签 IDF 与 MMR | 保留明确匹配的主体，给少量相邻题材探索位；取得“不感兴趣”反馈后才做可撤回的负向调整 |
| 近期偏好 | 口味接口支持时间窗口，发现当前使用全部时间 | 合并近期与长期证据，按事件时间衰减；单次浏览不足以改写偏好 |

行为原始记录留在本机；向公开目录查询只发送必要的人物、厂牌、系列、标签或番号。真实候选落库、后台采集和负向偏好学习需要另行定义来源、撤回口径与数据写入范围。

## 来源提示

来源返回多少评论就展示多少。公开 Web UI 的匿名评论分页已取得首两页不同记录，完整评论范围仍未取得；HTML 来源的部分评论限制不代表所有来源均需 VIP。资源提示说明本次取得范围并提供来源页，不推断用户账号权限。

资源协议用文字「磁链」「ED2K」「网页链接」。字节容量复用馆藏 `fmtSize` 口径显示，原始 URI 和来源容量字段保留；复制和下载使用原始链接。
